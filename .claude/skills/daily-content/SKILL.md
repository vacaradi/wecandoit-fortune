# 하루치 콘텐츠 생성 파이프라인

## 만드는 것

```
12띠 × 3연령대(student/worker/senior) = 36세트
```

각 세트는 이 순서로 이어집니다. **앞 단계 결과가 뒤 단계의 입력**입니다.

```
① 운세      오늘 무슨 일이 일어나는지
   ↓ (운세 점수와 내용을 근거로)
② 명언      옛사람도 그랬다는 위로
   ↓ (운세 + 명언을 근거로)
③ 부적      오늘 보완할 기운
   ↓ (전체를 근거로)
④ 넷플릭스   오늘 밤 볼 것
```

## 실행 순서

### 0단계 — 준비

```
1. content/pools/used-log.json 읽기
   → 최근 14일 소재, 30일 명언 인물, 30일 넷플릭스 작품 목록 확보
2. content/reference/gold-sample.json 훑기
   → 품질 기준선 확인
3. references/situation-pool.md 에서 오늘 쓸 소재 36개 선정
   → 최근 14일 사용분 제외
   → 같은 띠의 3개 연령대는 주제는 통하되 장면은 다르게
```

### 1단계 — 운세 36세트

`fortune-writer` 에이전트를 **띠별로 병렬 호출**합니다.
한 번에 12개(한 연령대씩) 또는 6개씩 나눠 돌립니다.

각 호출에 전달할 것:
```
날짜 / 띠 / 연령대 / 배정 소재 / 금지 소재 목록
```

받은 결과에서 확인:
- `score` 분포가 한쪽으로 쏠렸으면 조정 (90+ 8~12개, 40미만 3~6개)
- `aura` 6색이 고르게 분포하는지

### 2단계 — 명언 36개

`quote-curator` 를 호출합니다. **운세 본문과 score를 반드시 전달**합니다.

- 인물 중복이 나면 나중 것을 다시 뽑습니다
- `verified: false` 가 오면 그 명언은 버리고 재요청합니다

### 3단계 — 부적 36개

이건 에이전트 없이 직접 만듭니다. 규칙이 단순합니다.

```
운세에서 오늘 약한 부분을 찾는다
  → 그걸 보완하는 이름을 짓는다  (○○부, 4~7자)
  → 기원문을 만든다             (~하소서, 8~14자)
  → 왜 이 부적인지 한 줄         ("오늘 무너진 아침운을 세웁니다")
```

이름이 진지할수록 웃깁니다. `다이어트내일부`, `냉장고봉인부`, `읽씹방지부`.
같은 날 이름 중복 금지.

### 4단계 — 넷플릭스 36편

`netflix-picker` 를 호출합니다. **운세와 명언을 함께 전달**합니다.

- `verified: false` 면 그 작품은 쓰지 않습니다
- 작품 중복이 나면 나중 것을 교체합니다
- 새로 검증된 작품은 `content/pools/netflix-library.json` 에 추가합니다

### 5단계 — 저장

```
content/daily/YYYY/MM/YYYY-MM-DD.json
```
형식은 `references/format-spec.md` 를 따릅니다.

### 6단계 — 자동 검증

```bash
node scripts/validate-content.mjs content/daily/YYYY/MM/YYYY-MM-DD.json
```

실패하면 해당 세트를 고치고 다시 돌립니다. **통과할 때까지 반복합니다.**

### 7단계 — 검수

`content-checker` 에이전트에게 파일 경로를 넘깁니다.

- **반려되면 지목된 세트만 다시 만들어** 5~7단계를 반복합니다
- 통과할 때까지 배포하지 않습니다

### 8단계 — 이력 기록

`content/pools/used-log.json` 에 오늘 쓴 것을 기록합니다.

```json
{
  "2026-08-13": {
    "situations": ["1교시 졸음", "회의 길어짐", ...],
    "quoteAuthors": ["아리스토텔레스", "노자", ...],
    "netflixTitles": ["에밀리, 파리에 가다", ...],
    "talismanNames": ["정시기상부", ...]
  }
}
```

이 기록이 없으면 **일주일 만에 같은 내용이 반복됩니다.** 빠뜨리지 마세요.

## 여러 날치를 만들 때

날짜를 하나씩 순서대로 처리합니다. **병렬로 여러 날을 만들면 안 됩니다.**
앞날의 이력이 뒷날의 금지 목록이 되어야 하기 때문입니다.

```
8/13 생성 → used-log 기록 → 8/14 생성 (8/13 것을 피함) → …
```

## 품질이 무너지는 신호

아래가 보이면 즉시 멈추고 규칙 파일을 손봐야 합니다.

- 문장 구조가 비슷해지기 시작함 (`"~하려는 순간 ~합니다"` 반복)
- 소재가 도는 느낌 (풀이 말랐다는 뜻 → `situation-pool.md` 에 새 소재 추가)
- 명언 인물이 유명인 위주로 좁아짐
- 검수에서 "나쁘지 않은데 안 웃김"이 절반을 넘음
